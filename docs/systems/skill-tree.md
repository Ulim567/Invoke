# 스킬 트리 (노드와 선행 조건)

- 담당자: 임혜원

## 하는 일
- 스킬 트리의 노드와 선행 조건, 해금 재료를 표(`SkillTree` 에셋)로 담는다. 스킬 트리는 문법 요소와 C 스킬, 파이썬 스킬(#523), 자세 함수와 자세 규칙(#545)을 해금한다.
- 해금한 노드 목록을 받아서 "지금 해금할 수 있는지", "같이 열리는 노드", "이 블록을 쓸 수 있는지"를 알려 준다.
- 하지 않는 일
  - 플레이어가 무엇을 해금했는지 저장, 재료 빼기: 「재료 써서 스킬 트리 해금하기」 (임혜원, 이우림·박진우와 맞춤)
  - 재료 드롭·보관: 드롭 이슈
  - 스킬 수치(이름, 틱 수 등): `SkillTable` (c-skills.md, 박진우)

## 동작 규칙
- 에셋: `Assets/_HW/Resources/SkillTree.asset`. Inspector에서 고친다.
  - 처음 만들 때: Create → Invoke → Skill Tree → 에셋 ⋮ → 「기획서대로 채우기」 (`SkillTreeDefaults`)
  - 노드 설명은 에셋에 없음. 설명 표(`ItemDescriptions`, item-descriptions.md)가 노드 ID로 찾음. 문구를 고치면 에셋 메뉴 없이 바로 보임
    - 예전 「비어 있는 설명만 채우기」, 「설명 모두 다시 채우기」 메뉴와 `SkillTreeNode.Description`은 없앰. 에셋에 남은 옛 `description` 값은 에셋을 다시 저장할 때 지워짐
  - 코드(`SkillTreeDefaults`)에 노드를 새로 적은 뒤: 에셋 ⋮ → 「기획서에서 빠진 노드 더하기」. 에셋에 없는 노드만 맨 뒤에 더하고, 있는 노드(Inspector에서 고친 재료·메모)는 그대로 둔다 (#545)
  - 고친 뒤: 에셋 ⋮ → 「검사」. ID 중복, 없는 선행 노드, 선행 조건 순환, 재료, SkillTable과 스킬이 같은지, 자세 노드(아래)가 모두 있는지 본다.
- 노드 종류 (`SkillTreeNodeKind`)
  - `Syntax`: 문법. 해금하면 여는 블록(`UnlocksBlocks`)을 쓸 수 있고 그 블록을 1개씩 받는다
  - `Skill`: 스킬, 공통 이동, 자세 함수. 해금하면 그 함수를 쓸 수 있고 1개 받는다
  - `Rule` (#545): 자세 규칙. 해금하면 그 규칙의 이름·조건·효과를 볼 수 있다. 개수는 주지 않는다. 규칙 효과는 해금과 관계없이 처음부터 적용된다 (stance.md)
- 노드 ID
  - 스킬: `PredefinedFunctionIds`의 값 (예: `c.thrust`, `py.fireball`). 자세 함수 4개(`c.init_stance`, `c.get_stance`, `py.init_stance`, `py.get_stance`)를 빼면 SkillTable의 41개(C 24개, Python 17개)와 같아야 한다.
  - 자세 규칙: `c.stance.이름`, `py.stance.이름` (예: `c.stance.odd`). 자세 규칙 표(`StanceRule`)의 C 8개, Python 7개와 같아야 한다 (#545)
  - 문법: `syntax.이름` (예: `syntax.if`)
  - 한 번 정한 ID는 바꾸지 않는다. 플레이어의 해금 목록이 ID로 저장되기 때문
- 캐릭터 언어 (#523): 스킬 노드는 ID 앞부분으로 언어가 정해진다 (`c.` → C, `py.` → Python, `SkillTree.LanguageOfNode`). 문법 노드와 공통 이동(`common.`)은 모든 언어가 쓴다
  - 처음 노드(`StartingNodes`), 같이 열리는 노드(`AutoUnlockedBy`), 화면의 스킬 탭은 그 캐릭터 언어의 노드만
  - 서버 해금(`PlayerProgress.TryUnlock`)은 다른 언어의 노드를 없는 노드(`UnknownNode`)로 거부한다
  - 해금 목록은 캐릭터마다 따로라서 공통 노드(대시, 더블점프)도 캐릭터마다 따로 해금한다
  - 「검사」는 다른 언어의 노드를 선행으로 건 노드를 문제로 알린다 (그 캐릭터는 영원히 못 연다)
- 선행 조건: 적힌 노드를 **모두** 해금해야 열 수 있다. 같은 층의 노드(예: 상처 공략 / 검 깊이찌르기)는 각자 선행만 가지므로 어느 쪽을 먼저 열지는 플레이어가 고른다.
- `autoUnlock`: 선행 노드를 모두 해금하면 재료 없이 같이 열린다. 선행이 없으면 처음부터 해금된다.
- 스킬 이름은 SkillTable의 `DisplayName`을 쓴다 (노드에 이름을 적으면 그 이름).
- 스킬 노드는 이름 왼쪽에 아이콘(40×40)을 보인다 (#444, `SkillIcons.Get`, skill-icons.md). 아직 열 수 없는 잠긴 노드는 어둡게. 문법 노드는 아이콘 없음. 아이콘 자리는 `SkillTreeNodeView.ShowIcon`이 처음 쓸 때 노드 왼쪽에 만든다 (프리팹에 `Icon`을 넣어 두면 그것을 씀).
- **재료 수는 전부 임시다.** 재료 ID도 임시로 세 가지
  - `bug_fragment`: 버그 조각 (잡몹)
  - `field_boss_core`: 사냥터 보스 코어. 어느 보스인지는 기획, 드롭은 김도훈과 맞춘다. 떨어뜨리는 몬스터가 없어서 지금은 어느 노드도 쓰지 않음
  - `boss_core`: 레이드 보스 코어 (Gateway가 떨어뜨림). 검 소환, 마지막 단계 스킬

- 박진우와 정한 것 (#91)
  - 검 소환: 스킬 선행은 걸지 않고 보스 재료로 막는다. 레벨·진행도가 생기면 그 조건으로 바꾼다
    - 사냥터 보스 코어를 떨어뜨리는 몬스터가 없어서 레이드 보스 코어(`boss_core`)로 막는다. 사냥터 보스가 생기면 `field_boss_core`로 되돌린다
  - 패링: 선행 없이 재료만. 검 소환과 같이 열리는 것은 해제만
  - 대시 「저렙 구간」: 레벨이 아직 없어서 선행 없이 조각 2. 레벨이 생기면 레벨 조건으로
  - malloc·free 블록은 검 소환과 같이 연다 (malloc → 검 소환 컨셉)
    - #598부터 malloc·free는 블록 코딩에서 숨김: 검 소환 노드의 「여는 블록」 줄과 해금 카드에 나오지 않음. 노드 데이터는 그대로
- 블럭코딩 담당(임혜원)이 정한 것: 비교 블록은 if문, break·continue는 for문, 배열 만들기는 list와 같이 연다
  - 함수 블록(C 스킬, 사용자 함수)은 블록 종류가 같아서 문법 노드로 막지 않는다. C 스킬은 스킬 노드로, 사용자 함수는 「함수」 노드로 따로 확인한다 (화면에서)

### 자세 노드 (#545)
C·Python 캐릭터마다 9~10개. 자세 함수는 처음 개수가 없어(progress-store.md) 이 노드를 해금해야 쓸 수 있다. 규칙 노드의 선행 문법은 Notion 「캐릭터 자세와 소환검 기획」의 「해금」(판별에 필요한 문법이 열린 뒤).

| 노드 | 종류 | 선행 | 재료 (임시) |
| --- | --- | --- | --- |
| 자세 정하기 (`c.init_stance`, `py.init_stance`) | Skill | - | 조각 3 |
| 자세 확인 (`c.get_stance`, `py.get_stance`) | Skill | 자세 정하기 | 조각 2 |
| C 규칙: 적중(홀수), 일망타진(짝수), 신중함(5의 배수) | Rule | 자세 정하기, if문 | 조각 4 |
| C 규칙: 조급함(3의 배수), 흡혈(40~60) | Rule | 자세 정하기, 논리 연산 | 조각 4 |
| C 규칙: 혹사(소수), 지휘(피보나치 수), 완벽(완전수) | Rule | 자세 정하기, for문 | 조각 4 |
| Python 규칙: 직격(큰 수), 포화(작은 수) | Rule | 자세 정하기, if문 | 조각 4 |
| Python 규칙: 응축(4의 배수), 집요함(7의 배수) | Rule | 자세 정하기, 연산 | 조각 4 |
| Python 규칙: 경솔(회문수) | Rule | 자세 정하기, while문 | 조각 4 |
| Python 규칙: 비늘(완전제곱수), 각성(세제곱수) | Rule | 자세 정하기, for문 | 조각 4 |

- 자세 함수 노드의 이름(자세 정하기, 자세 확인)은 SkillTable에 없어서 노드의 `displayName`에 적는다. 규칙 노드의 이름은 자세 규칙 표에서 읽으므로 비워 둔다
- 자세 함수 노드는 아이콘이 없다 (스킬이 아님)

### 스킬 트리 화면 (#184)
- 스크립트: `SkillTreeView`(화면), `SkillTreeNodeView`(노드 프리팹). 스킬 트리 창(`Assets/_UL/UI/SkillTreeCanvas` 프리팹의 SkillTreePanel → Window, Base 씬) 안에 둔다. 로비와 연습장에서 열 수 있다 (`PlaceScenes.CanOpenSkillTree`, #586)
- 노드·선·계열 이름은 프리팹(`Assets/_HW/UI/SkillTree`)으로 만든다. 탭 버튼, 설명 글자, 해금 버튼은 창 안에 미리 놓아 둔다
- 탭: 문법 / 스킬 / 자세(#545). 스킬·자세 탭은 내 캐릭터 언어(`PlayerCharacter.LocalLanguage`)의 노드만 (#523). C 스킬 탭은 계열별 줄(소환, 찌르기, 던지기, 휘두르기, 이동), Python은 구슬, 원소, 범위, 보조, 이동. 줄 이름과 순서는 `SkillFamilies.COrder`·`PythonOrder`·`KoreanName`에서 읽음 (#578, 블록 편집 화면 함수 탭의 계열 소구분과 같은 이름·순서). 위치는 `SkillTreeView`의 `SkillLayout`·`PythonSkillLayout`·`SyntaxLayout`·`StanceLayout`·`PythonStanceLayout` 표. 표에 없는 노드는 맨 아래 「기타」 줄 (노드를 늘리면 표에도 넣는다)
  - 문법: 위에서 아래로 세로 한 줄 (순차 실행 → … → Type 정의), 줄 간격은 스킬 탭보다 넓음. 트리 칸보다 길면 세로 스크롤과 오른쪽 스크롤 막대 (#433)
- 같은 계열의 선행은 선으로 잇고, 다른 계열의 선행(검 소환)은 이름 아래 「+ 검 소환」
- 자세 탭 (#545, 이우림 결정 11/18: 처음에는 스킬 탭의 「자세」 계열이었으나, 규칙 노드를 한 줄에 놓고 선으로 이으면 앞 노드를 열어야 하는 줄처럼 보여 탭을 나눔)
  - 버튼: `LobbyUI` 프리팹의 탭 줄에 「자세」 버튼, `SkillTreeView.stanceTab`에 연결. 비어 있으면 자세 노드를 볼 수 없고 콘솔에 경고
  - 보이는 노드: 자세 정하기·자세 확인(Skill 종류지만 자세 탭)과 규칙 노드(Rule)
  - 첫 줄 「자세」: 자세 정하기 → 자세 확인. 그 아래는 규칙을 판별하는 데 필요한 문법마다 한 줄, 줄 이름이 그 문법 (문법을 여는 순서)
    - C: 「if문」 적중·일망타진·신중함, 「논리 연산」 조급함·흡혈, 「for문」 혹사·지휘·완벽
    - Python: 「연산」 응축·집요함, 「if문」 직격·포화, 「for문」 비늘·각성, 「while문」 경솔
  - 규칙 노드끼리는 선행이 아니라서 선으로 잇지 않고, 이름 아래 「+ 선행」 글도 적지 않는다(줄 이름이 문법을 알려 줌. 선행은 설명 칸 「선행」 행)
  - 줄 사이는 스킬 탭보다 조금 넓다 (`StanceRowGap`)
  - 해금 전 규칙 노드: 노드 이름·설명 칸 제목이 「???」, 「종류」 행은 「자세 규칙」. 설명 칸만(가운데 카드 없음)
  - 해금 뒤 규칙 노드: 규칙 이름, 「자세히 보기」를 누르면 가운데 설명 카드에 「자세 숫자가 2로 나누어떨어지지 않는 수인 경우, 아래 효과가 적용됩니다.」와 「효과:」 목록(좋은 효과 청록, 나쁜 효과 빨강) (`BlockReference.EntriesUnlockedBy`, item-card.md)

- 설명(설명 표 `ItemDescriptions.Get(노드 ID)`, item-descriptions.md): 하는 일은 문법 탭의 노드 옆, 설명 칸의 이름 아래에는 하는 일·용도·주의할 점 가운데 적힌 것. 비어 있으면 보이지 않음
- 해금한 노드는 해금 버튼 자리에 「자세히 보기」 버튼. 누르면 가운데에 설명 카드 「> 스킬」 / 「> 자세 규칙」(#545) / 「> 문법  if문」 (item-card.md). 문법 노드는 여는 블록마다 넘겨 봄. 잠긴 노드는 설명 칸만
  - 처음(#562)에는 해금한 노드를 누르면 바로 카드를 띄웠는데, 설명 칸만 보려 해도 매번 닫아야 해서 버튼으로 바꿈 (#545, 이우림 요청 11/19)
  - 띄울 카드가 없는 노드는 「해금됨」(누를 수 없음). 해제처럼 같이 열리는 노드도 해금 뒤에는 이 버튼이 보임
  - #544 때 설명 칸 안에 카드를 넣었다가, 칸이 좁아 긴 글이 튀어나가서(이우림 피드백) 팝업으로 바꿈
- 해금 직후 카드 (#544, 캔버스 9-3): 내가 요청한 해금이 성공하면 가운데에 「> 스킬 해금!」 / 「> 자세 규칙 해금!」(#545) / 「> 문법 해금!  if문」 카드 (item-card.md)
- 설명 칸: 제목과 내용을 위에서부터 쌓아 제목이 두 줄이면 내용이 밀림. 해금 버튼 위까지 넘치면 세로 스크롤 (`DetailScroll`, 노드를 고르면 맨 위로)
- 스킬 노드를 누르면 설명 칸 제목의 이름 옆에 블록 편집기의 함수 이름 (예: 검 찌르기  thrust, `BlockLabels.PredefinedFunctionName`)
- 노드를 누르면 설명 칸에 종류, 상태, 선행(열었으면 초록, 아니면 빨강), 재료, 같이 열리는 노드, 여는 블록
- 해금 목록은 `SetUnlocked`로 받는다. 받기 전에는 처음부터 해금된 노드(`StartingNodes` + 같이 열리는 노드)만 해금됨
- 「해금」 버튼은 `UnlockRequested`를 알리고, 내 캐릭터의 `PlayerProgress.RequestUnlock`을 부른다. 서버가 재료 확인·해금·저장을 한다 (progress-store.md 「노드 해금 검사」) (#294)
- 창이 열리면 내 캐릭터(`NetworkClient.localPlayer`)의 `PlayerProgress`에서 해금 목록과 재료를 읽고, `PlayerProgress.Changed`마다 다시 그린다. 해금하면 바로 「해금됨」으로 바뀐다
  - 재료는 「버그 조각 3/5」처럼 가진 개수/필요 개수 (모자라면 빨강)
  - `PlayerProgress.UnlockAnswered`가 실패면 설명 칸에 이유: `MaterialShort` 「재료가 모자라요」, `PrerequisiteMissing` 「선행 노드를 먼저 해금하세요」, `AlreadyUnlocked` 「이미 해금했어요」, 그 밖 「지금은 해금할 수 없어요」
  - 내 캐릭터가 없으면(네트워크 없는 시험) `SetUnlocked`로 받은 목록을 보여 준다
