# 협업 규칙

브랜치, 커밋, PR 규칙은 [README](../README.md)의 「작업 순서」를 따른다. 이 문서는 그 밖에 팀이 정한 규칙이다.

## 이슈 관리
- 이슈 목록은 Notion 「이슈 목록 (Alpha)」 한 곳에서 관리한다.
  - https://app.notion.com/p/bf435e08bfc64e4dbf7ee6b3c88d006a
- 상태는 이렇게 바꾼다.
  - GitHub 이슈를 만들면 Notion 상태를 「진행 중」으로 바꾼다.
  - PR이 dev에 병합되면 「완료」로 바꾼다.
- 「완료」가 늦어지면 그 이슈를 기다리는 사람도 늦게 시작한다. 병합과 상태 변경을 미루지 않는다.

## 할 일 고르기
- Notion 「이슈 목록 (Alpha)」의 「지금 할 수 있는 일」 보기에서 자기 이름 아래의 이슈를 고른다.
  - 「필수 선행」 이슈가 모두 「완료」인 이슈만 이 보기에 나타난다.
  - 아직 시작할 수 없는 이슈는 「기다리는 이슈」 속성에 무엇을 기다리는지 나온다.
- 이슈의 「기간」은 「늦어도 이날까지」라는 뜻이다. 일찍 끝나면 다음 이슈를 당겨서 시작한다.
- 다음 이슈를 고를 때는 다른 사람이 기다리는 이슈를 먼저 한다.

## 다른 사람과 맞추기
- 이슈의 「함께 맞출 사람」끼리 함수 이름, 데이터 형식 같은 접점을 직접 협의한다. 방법은 자유다.
- 협의가 끝나면 결과를 `docs/systems/`의 해당 시스템 문서에 기록하고, 그 기록을 작업 PR에 함께 넣는다.
- 기록하지 않은 약속은 AI가 모른다. AI는 `docs/systems/` 문서만 보고 다른 시스템을 사용한다.

## AI와 작업하기
- AI는 레포의 `CLAUDE.md`를 자동으로 읽는다. 공통 규칙은 그 파일에 있다.
- 대화는 시스템 단위로 하나씩 연다. 예: 「함수 실행기」 대화, 「C 스킬」 대화
- 대화를 시작할 때 AI에게 다음을 준다.
  - 맡은 이슈의 본문 (목표, 할 일, 완료 조건)
  - 관련 `docs/systems/` 문서
- 씬·프리팹 작업은 AI가 하지 않는다. AI가 안내하는 순서대로 사람이 에디터에서 한다.
- AI가 만든 코드도 본인이 이해한 뒤 PR을 올린다.

## 시스템 문서 (`docs/systems/`)

### 무엇인가
- 각 시스템이 다른 사람에게 무엇을 제공하는지 적은 문서다.
- 코드 설명서가 아니다. 다른 시스템과 맞닿는 부분(다른 사람이 부르는 함수, 읽는 값, 주고받는 데이터 형식)과, 그에 대해 다른 사람과 맞춘 약속만 적는다.
- 시스템마다 문서 하나를 두고, 양식은 `docs/systems/_template.md`를 복사해서 쓴다.

### 왜 필요한가
- 네 명이 각자 AI와 함께 코드를 만든다. AI는 다른 사람의 대화나 말로 한 약속을 모른다.
  - 문서가 없으면 AI가 다른 시스템의 함수 이름을 추측하거나, 비슷한 함수를 새로 만들어 버린다. 그러면 합칠 때 서로 맞지 않는다.
- 사람도 다른 사람의 코드를 열어 보지 않고, 무엇을 부르면 되는지 바로 알 수 있다.
- 「다른 사람과 맞추기」에서 협의한 결과를 남기는 곳이다.

### 언제 만드는가
- 다른 사람이 쓸 함수·값·데이터를 처음 만드는 이슈를 시작할 때 만든다.
  - 예: 함수 실행기, 데미지 계산, 몬스터 기본
- 다른 사람이 쓰지 않는 기능은 문서를 만들지 않아도 된다.
  - 예: 배경, 설정 화면
- 그 시스템의 담당자가 만든다.

### 언제 고치는가
- 「함께 맞출 사람」과 접점을 정했을 때
- 다른 시스템이 쓰는 함수의 이름, 받는 값, 돌려주는 값을 바꿨을 때
- 고친 문서는 그 코드 변경과 같은 PR에 넣는다. 문서와 코드가 따로 바뀌면 AI가 옛 문서를 보고 틀린 코드를 만든다.
- 문서는 그 시스템의 담당자가 고친다. 다른 사람이 바꿔야 할 때는 담당자와 협의한 뒤 고친다.

### 어떻게 쓰는가
- 다른 시스템을 써야 할 때
  1. 그 시스템의 문서를 연다.
  2. AI와 대화를 시작할 때 이슈 본문과 함께 그 문서를 준다.
  3. 문서에 적힌 함수와 값만 쓴다.
  - 예: 박진우가 C 스킬을 만들 때, 「함수 실행기」 문서를 AI에게 주고 문서에 적힌 실행기 함수로 스킬을 만든다.
- 문서에 필요한 것이 없을 때
  - 다른 사람의 시스템에 직접 함수를 만들지 않는다. 담당자에게 요청하고, 담당자가 함수를 추가한 뒤 문서를 고친다.

### 적지 않는 것
- 그 시스템 안에서만 쓰는 함수
- 코드를 어떻게 만들었는지에 대한 설명 (코드 주석에 쓴다)
- 진행 상황 (Notion 「이슈 목록 (Alpha)」에서 관리한다)
