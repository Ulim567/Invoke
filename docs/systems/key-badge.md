# 키 표시와 Tab 이동 (KeyBadge, TabFieldNavigator)

- 담당자: 임혜원

## 하는 일
- 버튼 안 글자 뒤에 그 버튼을 누르는 키를 작고 흐리게 보여 준다 (「들어가기  Enter」, 「닫기  ESC」). 앱 메뉴의 단축키 표시(저장 ⌘S)처럼 (`KeyBadge`, #430). 보여 주기만 하고, 키 연결은 `UIShortcut`·`InputBlockingPanel`(`OnSubmitKey`/`OnCancelKey`)이 한다
- 입력칸이 여러 개인 화면에서 Tab을 누르면 다음 입력칸으로 넘어간다 (`TabFieldNavigator`, #430)

## 동작 규칙
- 키 표시: 버튼 안에 `KeyBadge` 자식(글자 6, 높이 10, 640×360 기준)을 만든다. 테두리·바탕 없이 버튼 글자 색을 흐리게 (밝은 글자는 50%, 주황 버튼의 어두운 글자는 잘 보이게 75%) 1920×1080 캔버스는 3배. 레이아웃에 끼지 않고 마우스를 막지 않는다
  - 자리: 버튼 글자 뒤. 키 표시 + 4 + 버튼 글자를 묶어 버튼 가운데에 둔다 (버튼 글자에 키 표시 너비만큼 왼쪽 여백)
  - 글자가 한 글자 이하인 버튼(X)은 버튼 왼쪽 바깥에 둔다: 「[ESC] [X]」. 하지만 지금 화면들의 X에는 붙이지 않는다: 바로 옆 제목줄 글자(스킬 트리의 버그 조각 등)와 겹치고, X는 누구나 닫기로 안다. X도 ESC로 닫힌다
  - 다른 유명 게임(Hollow Knight, Dead Cells 등)처럼 버튼 안에 키를 함께 보여 주는 방식. 처음에는 버튼 모서리에 붙였으나 알림 표시처럼 보였고, 키 모양 상자도 버튼 위에서 튀어서 흐린 글자만 남김
  - 크기는 레이아웃이 잰다: 키 표시에 가로 레이아웃(양옆 3, 높이 11), 버튼에 가로 레이아웃(가운데 정렬, 간격 5, 버튼 글자 → 키 표시)
- 메뉴 Invoke → UI → 키 표시 붙이기(`KeyBadgeInstaller`, 에디터 전용)가 화면마다 붙인다. 레이드 방·레벨업 화면 만들기, 로비 입구 창 시안대로를 누르면 끝난 뒤 저절로 다시 돈다

| 화면 | Enter | ESC |
| --- | --- | --- |
| 로비 입구 창 (`LobbyUI`) | 들어가기 | 닫기 |
| 스킬 트리 창 (`LobbyUI`) | - | (X, 표시 없음) |
| 레이드 방 목록 (`RaidLobbyCanvas`) | 방 만들기 (창 열기) | 닫기 (X, 표시 없음) |
| 방 만들기 창 | 만들기 | 취소 (창만 닫음) |
| 비밀번호 창 | 입장 | 취소 (창만 닫음) |
| 파티방 | 시작(파티장) / 준비(파티원) | 나가기 (방 목록으로) |
| 레벨업 창 (`LevelUpCanvas`) | - | (X, 표시 없음) |

- 레이드 방의 키 (`RaidLobbyUI.OnSubmitKey`/`OnCancelKey`, 김도훈 파일): 떠 있는 창부터. 입력칸이 선택되어 있으면 `UIShortcut`이 Enter를 양보하므로 입력칸의 `onSubmit`으로 같은 버튼을 누른다. 버튼이 꺼져 있거나 누를 수 없으면(시작: 모두 준비 전) 아무것도 안 함. 방 만들기·비밀번호 창을 열면 첫 입력칸을 고른다
- Tab 이동: 화면 루트에 `TabFieldNavigator`. 로그인, 회원가입 (`AccountCanvas`), 방 만들기 창, 비밀번호 창
  - 키: `GameInput.UI.NextFieldPressed` (UI 맵 NextField, `<Keyboard>/tab`)
  - 대상: 켜져 있고 누를 수 있는 `TMP_InputField`만. 블록 코딩의 값 입력칸(`BlockField`)은 넣지 않음
  - 순서: 입력칸의 화면 위치 (위 → 아래, 같은 줄은 왼쪽 → 오른쪽). 마지막 칸 다음은 처음 칸
  - 지금 선택된 것이 그 화면의 입력칸일 때만 움직인다. 아무것도 선택되지 않았으면 맨 위 화면(`UIShortcut.IsTop`)일 때 첫 칸을 고른다
  - 입력칸에 Tab 글자가 들어가면 지운다

- 버튼 자리 (#430): 모든 창에서 확인(주황으로 채움)은 오른쪽, 취소·닫기(테두리)는 왼쪽. macOS·요즘 게임 관례이고, 우림이 시안을 따른 레이드 방 창들이 이미 이 순서라 맞춤

- 같은 방식으로 바꾼 곳 (#430): 설정 창 「돌아가기 … ESC」(오른쪽 흐린 글자), HUD 왼쪽 위 「설정 ESC」. 둘 다 예전에는 키 모양 상자(`hud_key`). HUD 바로가기의 1·2는 아이콘 자리라 상자 그대로

## 다른 시스템이 쓰는 것
| 이름 | 받는 값 | 돌려주는 값 | 설명 |
| --- | --- | --- | --- |
| `KeyBadge.Attach(버튼 RectTransform, 키 이름, 글꼴, 바탕 그림, 배율)` (static) | 버튼, "Enter"/"ESC", `TMP_FontAsset`, `Sprite`(비우면 단색), 640 기준 배율 | `KeyBadge` | 버튼 오른쪽 위에 키 표시를 붙인다. 이미 있으면 글자·크기만 바꾼다 |
| `TabFieldNavigator` (컴포넌트) | - | - | 입력칸이 여러 개인 화면(SetActive로 여닫는 오브젝트)에 붙인다 |

## 맞춘 결과
- 이우림 (#430): Tab 이동은 입력칸만, 순서는 화면 위치로 자동, `BlockField` 제외, 키 표시 문구는 `Enter` / `ESC`
- `RaidLobbyUI.cs`(김도훈 폴더)의 Enter·ESC는 #430 이슈 내용대로 고침 (PR에 적음)
