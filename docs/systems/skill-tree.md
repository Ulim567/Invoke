# 스킬 트리 (노드와 선행 조건)

- 담당자: 임혜원

## 하는 일
- 스킬 트리의 노드와 선행 조건, 해금 재료를 표(`SkillTree` 에셋)로 담는다. 스킬 트리는 문법 요소와 C 스킬을 둘 다 해금한다.
- 해금한 노드 목록을 받아서 "지금 해금할 수 있는지", "같이 열리는 노드", "이 블록을 쓸 수 있는지"를 알려 준다.
- 하지 않는 일
  - 플레이어가 무엇을 해금했는지 저장, 재료 빼기: 「재료 써서 스킬 트리 해금하기」 (임혜원, 이우림·박진우와 맞춤)
  - 재료 드롭·보관: 드롭 이슈
  - 스킬 트리 화면: 「스킬 트리 화면 만들기」
  - 스킬 수치(이름, 틱 수 등): `SkillTable` (c-skills.md, 박진우)

## 동작 규칙
- 에셋: `Assets/_HW/Resources/SkillTree.asset`. Inspector에서 고친다.
  - 처음 만들 때: Create → Invoke → Skill Tree → 에셋 ⋮ → 「기획서대로 채우기」 (`SkillTreeDefaults`)
  - 고친 뒤: 에셋 ⋮ → 「검사」. ID 중복, 없는 선행 노드, 선행 조건 순환, 재료, SkillTable과 스킬이 같은지 본다.
- 노드 ID
  - 스킬: `PredefinedFunctionIds`의 값 (예: `c.thrust`). SkillTable의 24개와 같아야 한다.
  - 문법: `syntax.이름` (예: `syntax.if`)
  - 한 번 정한 ID는 바꾸지 않는다. 플레이어의 해금 목록이 ID로 저장되기 때문
- 선행 조건: 적힌 노드를 **모두** 해금해야 열 수 있다. 같은 층의 노드(예: 상처 공략 / 검 깊이찌르기)는 각자 선행만 가지므로 어느 쪽을 먼저 열지는 플레이어가 고른다.
- `autoUnlock`: 선행 노드를 모두 해금하면 재료 없이 같이 열린다. 선행이 없으면 처음부터 해금된다.
- 스킬 이름은 SkillTable의 `DisplayName`을 쓴다 (노드에 이름을 적으면 그 이름).
- **재료 수는 전부 임시다.** 재료 ID도 임시로 세 가지
  - `bug_fragment`: 버그 조각 (잡몹)
  - `field_boss_core`: 사냥터 보스 코어. 검 소환을 초반에 못 열게 막는 데 쓴다. 어느 보스인지는 기획, 드롭은 김도훈과 맞춘다
  - `boss_core`: 레이드 보스 코어. 마지막 단계 스킬

각 문법은 앞 단계 문법이 선행 조건이다.

| 순서 | ID | 이름 | 여는 블록 | 재료 (임시) |
| --- | --- | --- | --- | --- |
| 1 | `syntax.sequence` | 순차 실행 | 함수 블록(C 스킬), 기다리기 | 처음부터 |
| 2 | `syntax.variable` | 변수 | 선언, 대입 | 조각 2 |
| 3 | `syntax.arithmetic` | 연산 | 연산 | 조각 3 |
| 4 | `syntax.if` | if문 | 조건문, 비교 | 조각 4 |
| 5 | `syntax.logic` | 논리 연산 | 논리, Not | 조각 5 |
| 6 | `syntax.for` | for문 | for, break, continue | 조각 6 |
| 7 | `syntax.while` | while문 | while | 조각 7 |
| 8 | `syntax.function` | 함수 | return (사용자 함수 만들기) | 조각 8 |
| 9 | `syntax.list` | list | 배열 만들기 | 조각 10 |
| 10 | `syntax.type` | Type 정의 | (블록 아직 없음) | 조각 12 |

- 박진우와 정한 것 (#91)
  - 검 소환: 스킬 선행은 걸지 않고 사냥터 보스 재료로 막는다. 레벨·진행도가 생기면 그 조건으로 바꾼다
  - 패링: 선행 없이 재료만. 검 소환과 같이 열리는 것은 해제만
  - 대시 「저렙 구간」: 레벨이 아직 없어서 선행 없이 조각 2. 레벨이 생기면 레벨 조건으로
  - malloc·free 블록은 검 소환과 같이 연다 (malloc → 검 소환 컨셉)
- 블럭코딩 담당(임혜원)이 정한 것: 비교 블록은 if문, break·continue는 for문, 배열 만들기는 list와 같이 연다
  - 함수 블록(C 스킬, 사용자 함수)은 블록 종류가 같아서 문법 노드로 막지 않는다. C 스킬은 스킬 노드로, 사용자 함수는 「함수」 노드로 따로 확인한다 (화면에서)

## 다른 시스템이 쓰는 것
- 코드 위치: `Assets/_HW/Scripts/SkillTree/`
- 해금 목록(`unlocked`)은 해금한 노드 ID들. 저장은 「재료 써서 스킬 트리 해금하기」에서 정한다.

| 이름 | 받는 값 | 돌려주는 값 | 설명 |
| --- | --- | --- | --- |
| `SkillTree.Instance.Nodes` | - | `IReadOnlyList<SkillTreeNode>` | 모든 노드. 스킬 트리 화면에서 쓴다 |
| `SkillTree.TryGet(id, out node)` | 노드 ID | `bool` | 없으면 false |
| `SkillTree.StartingNodes()` | - | `List<string>` | 처음부터 해금된 노드 (순차 실행, 검 찌르기, 검 던지기). 새 캐릭터의 해금 목록 |
| `SkillTree.CanUnlock(id, unlocked)` | 노드 ID, 해금 목록 | `bool` | 선행을 모두 해금했고 아직 해금하지 않았으면 true. 재료는 보지 않는다 |
| `SkillTree.AutoUnlockedBy(unlocked)` | 해금 목록 | `List<string>` | 해금한 뒤 부른다. 같이 열리는 노드들 (예: 검 소환 → 해제). 이것도 해금 목록에 넣는다 |
| `SkillTree.IsBlockUnlocked(kind, unlocked)` | 블록 종류, 해금 목록 | `bool` | 편집 화면에서 이 블록을 쓸 수 있는지. 어떤 노드에도 없는 블록은 true |

### `SkillTreeNode`
| 이름 | 설명 |
| --- | --- |
| `Id`, `Kind` (`Syntax` / `Skill`), `DisplayName` | |
| `Prerequisites` | 선행 노드 ID들 (모두 필요) |
| `AutoUnlock` | 선행을 채우면 재료 없이 같이 열림 |
| `Cost` | `MaterialCost`(`MaterialId`, `Count`) 목록 |
| `UnlocksBlocks` | 해금하면 쓸 수 있는 블록 종류 |
| `Note` | 가정한 것 |

## 맞춘 결과
- 박진우와 정한 것 (#91)
  - 스킬 노드 24개 = SkillTable 24개 (「검사」가 확인함). 이름은 SkillTable의 이름을 그대로 쓴다. 스킬이 늘거나 ID가 바뀌면 검사에서 걸리므로 그때 같이 맞춘다
  - 해금 경로는 「C 캐릭터 - 1차」 그대로. 바꾼 것은 위 「박진우와 정한 것」 (기획 문서도 박진우가 고침)
- 정해야 할 것
  - 공통 노드(대시 `common.dash`, 더블점프 `common.double_jump`): 다른 캐릭터 트리가 생기면 캐릭터마다 따로 열지, 한 번 열면 같이 열릴지
  - 검 소환을 막을 보스 (기획), 보스 재료 드롭 (김도훈)
  - 스킬 사용 조건의 가정 3개(패링 맨손 불가, 표식 남기기 소환검 필요, 해제 소환검 있어야 사용)는 c-skills.md 「가정한 것」을 따른다
- 이우림과 맞출 것 (「재료 써서 스킬 트리 해금하기」에서)
  - 해금 목록을 노드 ID로 저장하는지, 재료 ID
